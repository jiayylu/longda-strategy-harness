# v7 部分构造与 CP 接力

主模型和通用构造仍可并行。模型可以编写完整构造程序，也可以提交部分尝试；无需把“模型程序独立完成160道”作为唯一成功路径。

## 接力资格

程序错误、完整审计失败、工作进程错误、目标上界剪枝不自动提交补全。构造死路、墙钟/资源额度结束时，若worker保存了结构有效且非空的部分数组，可以提交一次补全。资格只是数据可用，不代表已经证明后续可行。

## 补全语义

- 模式明确为partial_complete，与原改善模式分开。
- 只使用本次部分数据的AddHint，当前完整基线不能覆盖它。
- 不固定提示值、不增加改善阈值、不绑定策略的局部释放范围；工艺和观察事实仍完整约束。
- 求到首张完整解后结束本次补全；通过物理、观察状态和完整模型验算后才记录有效候选。
- 提示采用当前数据中的保温/锻打起止和炉号；车辆相关决策由CP自行求解。
- 不把SAT模式的OPTIMAL状态当作锻打目标已最优。

## 两个出口

成功：保存候选，和共享最好方案按原目标比较；更差候选不覆盖基线。完整结果进入对应构造记录，后续同构造的新改善策略可以复用它。

未成功：保留原构造原因，附加CP状态、提示数量、耗时、证据编号，反馈模型。UNKNOWN不当无解；CP提示可修改，因此不能将补全INFEASIBLE解释为只否定原31道固定选择。无可行解证明仅按实际完整模型范围解释。

## 并发、额度、恢复

补全与改善共用cp-workers容量。每个不同部分提示一次补全，不按UNKNOWN自动扩时重跑。待补全策略暂停其他依赖任务，反馈汇总等待补全结束；其他合法基线的搜索不受影响。相同任务重放只记一次真实执行。

普通构造结果和模型run_algorithm工具结果均走这条路径。工具返回“已排队”不等待长求解；模型可以继续处理反馈，后续CP结果按原策略身份统计。

检查点保存补全任务、原失败、提示内容哈希和去重集合。用户停止不自动重启，显式恢复后重跑未结束的CP任务；没有保存CP内部树。
