## 谁执行什么

- 主模型决定尝试什么算法，可以读取源码、提交完整构造代码、执行小试验、查看失败后继续改。
- 生成的构造代码决定候选选择、分支与回退；资源环境负责实际时间与动作是否合法。
- CP-SAT既可检查固定前缀是否能补全，也可在指定改排范围内真正搜索。返回INFEASIBLE只对当次固定条件成立。
- 校验器不听模型的“成功”声明；完整排程通过两套检查才更新共享基线。
- 摘要模型和Memory updater整理可复用经验，不修改规则、不宣告可行、不存未来排程答案。

## 两条循环

**修复循环：**算法失败 → 保存具体错误、拒绝原因、已承诺状态和源码 → 模型读取/改写/试运行 → 修订算法重新执行。修复调用有显式额度，额度耗尽保留待处理证据，不能写成“无解”。

**改善循环：**完整合法方案 → CP局部改排或新的构造算法 → 双审计 → 与当前共享最好结果比较 → 实测收益反馈给模型与Memory。候选当日成绩更高但后续不合法时，不更新基线。

不同策略可以并行，谱系编号贯穿源代码、构造、CP和反馈。当前模型工具步骤在同一个主模型回合内顺序执行；不是新增多个主模型同时思考。

## 可恢复到什么程度

运行检查点恢复队列、策略、经验和最好合法方案。生成算法需要显式把自己维护的前沿传给 `checkpoint`；不调用就只能重跑该算法。代码/输入/环境不匹配时拒绝旧检查点。CP内部搜索树和模型内部思考不保存。中断后未知工具结果保留为UNKNOWN，不补造成功或无解。

## 仍需实测的部分

完整算法开放、时间窗和日历修正解决了原引擎表达能力的缺口；不自动保证模型写出的算法更快、更优。一次小样本成功不能证明稳定性。冲突反馈包含规则、工序及当前预订，不是已经求得最小不可满足核心；回退策略仍需算法选择与试验。
