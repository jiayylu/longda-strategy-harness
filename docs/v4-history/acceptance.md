## 3. 短测中进一步修正的细节

- 模型回复只有 name、summary、hypothesis 等展示文字超长时，裁剪展示文本并记录事件，不再浪费一次模型调用。完整原始答复保留。分组、数量、程序、范围、证据等可执行字段仍严格验证。
- 最新具体失败不重复放入历史列表；历史修订只保留最近三条进入当前请求，原文仍留在运行产物。
- 未结束的工具调用在显式恢复时补记 OUTCOME_UNKNOWN；不会凭中断就标无解。
- 显式恢复提高 repair-attempts 时可继续原来额度耗尽的修正链，历史调用次数不清零；不自动重启。

## 4. 边界和下一步

- 本轮完成的是执行闭环与可追溯反馈，不能保证模型提出的新贪心逻辑一定能完成 160 道工序。真实测试仍暴露策略质量不足。
- 最新失败现场被固定保留，但不是最小冲突集或不可满足核心；模型仍需区分“某分支死路”与“整个问题无解”。
- 扩展构造器有逐候选拒绝与预订现场诊断；保留的 legacy 引擎只提供原有较粗进度/部分结果，没有为补日志而修改其规则代码。
- 下一步适合针对已记录的具体死路做短小、同条件的策略比较；没有证据支持直接再跑几十分钟的广域 CP。
- 两个 qwen3.7-plus 辅助角色保持现有实现；本轮隔离测试关闭它们，避免把摘要/Memory/基线产生混成模型纠错效果。
