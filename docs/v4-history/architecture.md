# v4 模块职责与两条执行路径

## 主体角色

| 模块 | 文件 | 输入 → 输出 |
|---|---|---|
| 启动 | `start.py` | 参数与隐藏凭据 → Node 编排进程 |
| 主模型调用 | `src/client.ts`、`prompts.ts` | 订单/在制事实、经验、工具结果 → 结构化策略；不执行排程 |
| 策略权限 | `src/contracts.ts` | 策略 JSON → 数量守恒、枚举值、范围校验后的配置 |
| 任务编排 | `src/cli.ts` | 任务队列、共享最好方案 → 构造/CP/主模型/辅助任务调度 |
| **修正循环** | `src/repair.ts` | 持久失败单 → 原始证据、修订链、待处理/已回答/额度耗尽状态 |
| **改善循环** | `src/strategy_cycles.ts` | 策略及全部后续任务 → 归因统计、反馈批次、显式暂停原因 |
| 执行边界 | `src/worker.ts` | 有限额度任务 → Python 子进程、取消、结构化输出；不向子进程传模型密钥 |
| 构造 | `python/constructor.py`、`legacy_constructor.py` | 当前订单 + 合法候选 + 排序策略 → 完整候选或具体失败现场 |
| 程序限制 | `python/program.py` | rank 源码 → 受限计算；不可改候选合法性、外部文件或硬约束 |
| CP 搜索 | `python/worker.py`、`physical_model.py` | 已审计提示、当前基线、选定放开订单 → 完整模型搜索 |
| **CP 去重** | `python/search_registry.py` | 实际模型和求解输入 → 原子登记/跳过完全重复任务；不是物理可行性剪枝 |
| 校验 | `reference/`、`verification.py`、`production_state.py` | 完整排程 → 物理审计、完整模型逐项验算、已执行事实审计 |
| 评分 | `python/scoring.py` | 完整合法方案 → 当日净锻打、同分保温偏好 |
| Memory | `src/memory.ts` | 场景特征 + 证据 → 多候选参考、收益记录、版本化经验卡 |
| 辅助模型 | `src/auxiliary.ts`、`auxiliary_roles.ts` | 裁剪旧事实 → 独立摘要；事实+卡片 → 独立增改退役建议 |
| 恢复/事实日志 | `src/checkpoint.ts`、`events.ts` | 队列、修正单、已审计基线 → 原子检查点、call/result 对应事件 |

## 一条失败策略如何走

1. 主模型返回 `round-1/strategy-1`；策略得到稳定编号。
2. 工具执行生成 `task-N/attempt`，先记录 `tool_call`。
3. 假设返回 `PROGRAM_ERROR: Forbidden call results.append at line 13`。原始结果、程序与文件路径落盘，`tool_result` 使用同一 call_id。
4. 本策略状态变为 `construction_repair`，删除尚未执行的本策略任务，不启动其 CP。其他已审计方案不受影响。
5. 待修正问题进入 `Repairs`。下一次主模型调用优先读取它，而不是再等一个正常搜索批次。
6. 模型返回一个修订策略。只改 CP 参数、重复原拒绝代码、引用不存在的证据会被拒绝，并把具体拒绝理由带入下次修正。
7. name、summary、hypothesis 超长只裁剪展示，完整原文仍保存；可执行字段不放宽。通过策略格式校验后建立新的策略编号，用 `repaired_from` 连接前一版本；重新执行构造。
8. 若仍失败，继续这条修订链，受 `repair-attempts` 和整场额度约束。失败类型与结果原样保留。
9. 只有完整方案经过双重校验，才发布基线并开放 CP 改善。

构造的 `failure_context` 描述的是当前分支已承诺的时间和资源，不是现实工厂快照，也不是后续可行性证明。`rejections` 表明哪些候选在该分支被排除；模型提出的根因解释仍是待验证的假设。

## 一条合法策略如何继续改善

1. 完整合法构造可以立即作为基线；不等 CP 结束。
2. CP 根据该策略的 direction、fraction 或 focus_orders，重新选择本次放开的订单，其他安排固定。
3. 使用完整四天工艺、炉、压机、车辆约束；已有基线时加入当日成绩改善条件。可选同分保温偏好保持原语义。
4. 实际输入登记去重，跨并发进程使用文件锁。策略名称不同但实际输入完全相同，不重复执行。
5. 合法改善在发布时与最新共享基线比较；UNKNOWN、不完整前缀、模型口头预估都不能更新基线。
6. 未改善尝试可更换种子、增加单次额度，但不擅自扩大范围。达到反馈条件后暂停本策略，主模型根据已完成批次决定继续、明确扩大或换策略。
7. 同一场景有多个策略时可以并发；来源编号贯穿构造、CP、反馈与 Memory，避免将别的策略收益归给当前策略。

## 事实、摘要、Memory 的边界

- 原始工具结果与模型答复保存在本次运行中，是可核对的证据。
- 最新待修正的错误现场直接进入主模型请求，不能被辅助摘要覆盖或被大量 CP UNKNOWN 挤掉。
- qwen3.7-plus 摘要只压缩较旧反馈；失败则回退程序摘要，不阻塞求解。
- 独立 qwen3.7-plus Memory updater 只能提出结构化增/改/退役；程序校验证据、版本和规则域，数值收益由程序计算。
- 经验只保存条件性策略与聚合特征；本次运行的具体排程、部分时间表与车炉预订留在任务文件/检查点中，不写进可复用经验。

## 中断语义

停止后等子进程清理，保存队列和基线。显式恢复时校验代码、输入、规则与目标；未收到结果的工具调用补记 OUTCOME_UNKNOWN。此类任务属于只读求解，可重新计算，但不声称恢复了 CP 的内部搜索树。模型请求也可能需要重新调用，因此会消耗新额度。已确认提交的合法方案恢复后重新校验。
