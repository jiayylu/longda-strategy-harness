# v12 改动记录

用户本次要求先修改，不做测试。因此本版不运行搜索、基准对照、模型 API 或回归测试；编译检查不启动排程。

## 修改范围

- `src/task_pool.ts`：换轮仅考察当前可用范围，不要求全部工作任务空闲；当前任务的排队/占用仍排除。修正扫描游标按实际扫描位置前进。
- `src/generic_cp_policy.ts`：新增通用任务冷却账本。请求身份包含启动基线、提示、方向/范围、偏好及配置额度/线程；随机种子不改变身份。实际执行范围单独按基线、提示及已释放订单累计。
- `src/cli.ts`：接入资格筛选、同请求并发限制、冷却观察和再探；暂缓任务不占任务池供给额度，仍保留在队列。冷却不结束整场，已有有收益路径保留。
- `src/events.ts`、`src/search_statistics.ts`：增加换轮、冷却、恢复事件及统计。记录的是资源安排，不是假设无解。
- 包版本、默认经验库、README 更新到 v12。

模型策略的既有反馈规则继续独立运行；新冷却只作用于通用 CP 改善，包括从原始 CP 经验生成的通用任务，不干扰补全和低分结构探测的单独额度。

## 边界

- 不改变 Python 构造/推理引擎、工艺范围、车辆规则、审计规则或目标。
- 没有承诺 870 分钟一定可达，也没有证明提速或 Memory 收益。
- 冷却阈值 3 次、90 秒未验证为最佳配置。
- 同方向不代表同范围：不同请求范围仍可试；同请求的随机种子变化不会绕过冷却。
- 实际范围只有 CP 返回后才完全确定，因此不同请求第一次产生相同实际范围时仍可能发生一次重复计算；后续按已记录证据控制，不提前编造实际释放订单。
- 不把实际冻结文件哈希核对冒充排程回归测试。

部署记录保存在 `verification/deployment-v12.json`；旧版完整性记录为 `verification/v11-source-before.json`。
