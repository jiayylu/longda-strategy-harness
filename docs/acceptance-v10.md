## 实现范围

- 空 `tool_calls: []` 在严格业务校验前规范化；非空工具调用与候选混排明确纠错，不静默删字段。实际 v9 失败答复已纳入回归样本，两个候选可通过完整“返回解析→当前场景/证据校验→任务配置展开”链路。
- 物理版本和搜索版本分开；只因基线提升不再重启模型思考，CP 启动时使用最新合法基线。物理变更仍需要确认。这不等于已经增加了在线插单功能。
- 通用滚动任务池提供不同方向、子集、范围；按实际收益分配额度。至少保留一条旧的连续改善链；模型策略和程序生成任务分别归因。`--portfolio-refill off` 可关闭新任务供给，保留其他修复。
- 模型未交付有明确原因；辅助模型的回退/拒绝也独立统计，不能用主模型 errors=0 概括全部辅助调用。
- 补全无成功时降低资源份额，保留探索；UNKNOWN 不视为无解。
- 每个普通任务记录算法修改和观测对比，Memory 保留适用状态、父证据、差异与因果归因限制。辅助模型可以不生成新卡，不能把检索命中或最终分数等同于策略有效。

## 真实模型检查

单独180秒预算，模型、构造、搜索、审计都计时；低推理额度、1轮规划、最多1次修正。主模型 qwen3.8-max；摘要及经验更新 qwen3.7-plus。使用独立测试经验库，不污染正式库。

- 总墙钟 **183.09秒**（含停止清理）；首张合法方案 **5.50秒**；最好 **692分钟 / 48.06%**，完整审计通过。
- 约30.8秒：主模型返回2条策略，空协议字段被正常规范化；即使基线已经提高，也没有触发重想。
- 其中一条构造配置已有失败证据，立即返回具体失败并启动修正，没有为相同失败再空跑构造。
- 约57.4秒：收到修正后的1条策略，正常接受；其构造配置也命中了已有失败记录，反馈保留。不能把“接受修正”说成“修正成功”。
- 合计2次主模型请求、3条被接受策略；1次新的模型策略关联 CP 尝试，结果 UNKNOWN，**模型策略没有产生已验证的改善**。其他候选走了缓存证据反馈，不能计为新执行。
- 通用搜索将最好方案提高到692分钟；不能把这个分数归因于主模型。
- 5次补全均未成功。资源限制生效，但没有补全有效性的证据。
- 辅助模型：15次摘要、11次 Memory 更新调用，3次应用更新；1次因证据数组超过20项回退，其余部分调用合理返回无更新。正式发布补明每条卡最多20个证据的提示，并增加辅助结果单独汇总。并行调用耗时之和不能当作整体墙钟。
